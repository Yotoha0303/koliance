## 1. 主题：两条线程 + 一条连接

| 线程 | 交付物 | 状态 |
| --- | --- | --- |
| **A · 链上可验证的永续** | `Vault.sol` / `PositionManager.sol` / **逐块资金费率**（`ADR-003`）/ Go 清算 Bot | 已实现；**未部署** |
| **B · Agent 信任与身份**（#1 前半） | **链上身份**：`Koliance.sol`——`Identity` + 可信证明链 `TrustRecord{from, to, action, proof, timestamp}`（已有）<br>**链上委托**：`SessionKeyRegistry.sol`——EIP-712 授权 + 限额 / 日窗口 / 撤销 / 冻结（**已建，19 例测试**）<br>**链下**：`agentcard` 委托限额 → **升级为 EIP-712**（**未做**，需 Go 侧重依赖决策） | 链上已完成；**链下未升级** |
| **连接**（#1 后半） | **高性能结算支持的自治 Agent 基础设施**——Agent 持 Session Key 在链上交易：A 提供可交易的机制，B 提供"谁能交易"的授权 | 待做 |

### 关于「如 ERC-8004 类实现」—— 本仓不需要引入新标准

`想法记录.md` 的措辞是「**如** ERC-8004 **类**实现」，即**这一类做法**，不是要求实现该标准本身。
本仓**已有该"类"的实现**，无需从零引入：

- `contracts/contracts/Koliance.sol` —— 链上身份（`identities`）与**可验证的信任记录**
  （`TrustRecord{from, to, action, proof, timestamp}`）。这就是"信任与身份机制"的链上落点。
- `backend/internal/agentcard/` —— 委托的**限额与约束**（限额 / 日限 / 白名单 / 冻结 / 批次归集），
  约 70% 的 P0 已存在。**升级它**补 EIP-712 验签，而不是并排再建一套（`ADR-004` D3）。

### 关于「高性能结算」—— 已被 `ADR-004` 明确降范围

`ADR-004` D2 裁定：**本次不做 10,000 TPS 的链下预扣**（本地 Redis 对评委不可验证），
改为**授权走 B、执行落在 A 的链上合约**，每一步都产生 tx hash，
满足"Judges need to be able to verify what you built"。若确需额度预扣，**用已有 PG 事务**。

**原则**（#3）：**核心功能展示优先，数据采用模拟数据优先**。不要把演示卡在外部依赖上。

**范围**（#4）：只做 立项/需求/设计/开发/测试/发布；**不做**运维/故障/迭代/自动化——交平台处理。

## 2. 线程 A：链上可验证的永续（对标 GMX v1 单池）

用最稳的模型做出最直观的 Hardcore Demo。不从零发明复杂 AMM 算法，优先成熟、稳定、抗风险的模型。

**核心合约模型（单池/金库模式）**

- 简单流动性金库 `Vault`，支持存入 USDC 作为对手盘。
- 用户质押保证金，选择方向（做多/做空美股标的，如 NVDA / TSLA / BTC）与杠杆倍数。
- **逐块资金费率**（`ADR-003`）——赛道靶心，Monad 原生叙事。

**预言机**

- Pyth Low-Latency Pull Oracle。⚠️ **实测：美股 feed 在 Monad 上不可用**
  （见 `docs/planning/执行方案-后端与合约.md` §0.2）。演示走可控的 `DemoOracle` 路径，Pyth 作为生产路径讲。

**链下清算 Bot（Go）**

- 监听链上开仓头寸与实时价格流；保证金率低于维持阈值时并发调用 `liquidate()`。

**路演演示亮点**：前端手动调低模拟价格，大屏展示 Go Bot 在不到 1 秒内高并发完成数十笔链上自动清算。

## 5. 落地顺序（黑客松冲刺基准）

> **顺序已被 `ADR-004` 修正**：`推荐方案` §3.1 指出 RFC 把"链上资产"排在 P2 是错的——
> **可验证性优先**。故先让链上有东西，再谈链下性能。

**P0（死保）**：修合约 4 个 P0 缺陷（GAP-01~04）→ perp 栈部署到 Monad → 前端接线 → Go 清算 Bot
**P1**：逐块资金费率（✅ 已完成）→ **EIP-712 授权 + Session Key 链上登记（✅ 链上已建，见 `013`）** → 清算结果大屏
**P2**：复式记账 `settlement_ledger`（RFC DDL 可直接用）→ ZK Verifier 抽象插槽（只留接口）

**时间不足时的砍单顺序**（先砍 → 死保）：
`ZK 插槽 → Redis 预扣 → 复式记账 → 清算大屏 → EIP-712 → 逐块资金费率 → 清算 Bot → 部署 → 修 P0 合约缺陷`

**原始技术分解**（阶段划分、接口冻结、K 线等细节）：见 `docs/planning/推进方案.md` 与 `docs/planning/执行方案-后端与合约.md`
——**但这两份的排期部分已过时**，取舍以本文件的 P0/P1/P2 与 `ADR-004` 为准。
