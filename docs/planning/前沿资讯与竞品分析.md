## 第二部分：前沿资讯

### 2.1 Pyth —— 你们的技术栈，最近三个月有三个变化

**(a) Pyth 获批成为 Nasdaq Basic 的分销商（2026-09-22）**

> "Nasdaq's proprietary real-time quote and trade product for U.S. equities via data feeds."

Pyth 现在能合法分销纳斯达克的实时美股报价。**这意味着你们要做的"美股永续"在数据合法性上踩在实处**，不是拿个山寨行情源糊弄。路演时这是一个能讲的点。

**(b) Pyth Index 产品 —— 24/7 指数**

> ⚠️ **更正（2026-10-06）**：本节原本推荐用 `Equity.Index.*` 解决"美股喂价空窗"。**该建议已被链上实测证伪** —— `Equity.Index.*` 在 Hermes 元数据里存在，但**没有部署到 Monad 的 Pyth 合约**（`priceFeedExists` 返回 false）。下面保留原文关于 Index 机制的解释（它仍然准确），但结论已改。

关键设计说明（直接引用）：

> "a 24/7 index doesn't mean the underlying exchange trades every second — it means the index **follows a defined methodology during the hours when traditional markets may be closed**."

**Index feed 不是实时股价**，是按既定方法论在闭市时段推演的指数。这个机制理解仍然有用——它解释了为什么 Index 与 US 两类 feed 会并存。

**但 Monad 上只有 `Equity.US.*`，且已 143.5 天未更新**（详见 `执行方案-后端与合约.md` §0.2）。实测结果：

```
priceFeedExists(Equity.Index.NVDA/USD)  -> false
priceFeedExists(Equity.US.NVDA/USD)     -> true   (但 publishTime 是 143.5 天前)
priceFeedExists(Crypto.BTC/USD)         -> true   ($83,106.30，新鲜)
```

**修正后的结论**：Monad 测试网上**美股喂价实际不可用**，演示必须靠 `DemoOracle`。这不是"用哪个 feed"的问题，是"这条链上没人推送美股更新"的问题 —— 拉取式预言机只在有人提交更新时才更新，测试网上没人提交。

**(c) 美股公司行为数据（corporate actions）即将上线**

分红、拆股这些会影响永续合约的结算价。目前 Pyth 还没有。**如果评委里有衍生品背景的人，这是最可能被问到的技术问题**。准备一个"当前用 Index feed 规避、公司行为数据上线后接入"的回答。

**(d) Lighter 正在用 Pyth Index 拓展非加密永续**

Lighter 是基于以太坊 zk rollup 的永续交易场所，正在评估用 Pyth Index 把永续市场从加密扩展到股票等 RWA。覆盖资产类别：**股票、商品、金属、FX、期货**。

**这段话值得逐字读：**

> "Adding a market involves more than listing a symbol — regional calendars, market structure, and data availability all matter, along with how the product gets priced outside normal sessions."

——**"如何给正常交易时段之外定价"正是你们要解决的核心问题**，也是最该在路演里主动讲的技术点。

来源：[Pyth Blog](https://www.pyth.network/blog)、[Lighter 一文](https://www.pyth.network/blog/lighter-explores-pyth-indices-as-it-expands-perpetual-markets-beyond-crypto)

## 第三部分：竞品分析

### 3.1 Perpl —— 最直接的同链竞品 ⚠️

| 项 | 内容 |
| --- | --- |
| 机制 | **完全链上 CLOB**（中央限价订单簿）永续，明确宣称 "No off-chain matching engine" |
| 链 | Monad |
| 进度 | 2026-07 累计成交已破 **$1B** |
| 标的 | 目前主打 BTC 杠杆 |
| Gas 目标 | post + cancel < 100k gas |

**他们官网的口号就是你们 Track 1 的题目：**"Trade Bitcoin with leverage on Monad"，"CLOB-based perpetual futures DEX"，"No off-chain matching engine"。

**Perpl 缺的东西是有意为之：** 他们的 docs 完全没有描述**清算引擎**，预言机也只有一句"perps generally just need a price oracle and a stablecoin for margin"。这是个 CLOB，不是池子模式。

**对你们的定位含义：**
- ❌ **不要跟 Perpl 比"链上订单簿"** —— 他们这个叙事已经占住了，而且有真实成交。
- ✅ **你们的机制本来就不同**：GMX v1 式的**金库对手盘（Vault as counterparty）**，LP 承担对手方风险，用户不依赖做市商报价。
- ✅ **Perpl 是纯加密（BTC）**，你们是 **RWA 美股** —— 标的维度不重叠。

### 3.2 Kuru —— 不是竞品，但可能是 bounty 通道

- Monad 上的**混合 CLOB-AMM 订单簿 DEX**（"fully onchain order book + aggregator"）
- 融资 $11.6M，**Paradigm 领投**，Electric Capital 参投
- 只做现货，不做永续
- **Metropolis 有 Kuru 的 $5,000 × 2 bounty**

→ 如果你们的 Vault 需要现货流动性参考，或想拿 bounty，值得接触。

### 3.3 Ostium —— 最像你们的产品，但它是公司不是黑客松项目 🔴

| 项 | 内容 |
| --- | --- |
| 定位 | **"API-First Infrastructure for Global Perpetuals"** —— RWA 永续 |
| 标的 | **股票、指数、商品、FX、加密**，70+ 市场 |
| 规模 | 累计成交 **$53B+**，单笔最大 $26.45M（黄金，0.018% 滑点） |
| 模式 | "Post margin, not notional" |
| 投资方 | **GSR、Wintermute Ventures、Jump、General Catalyst、Coinbase Ventures、LocalGlobe** |
| 客户 | 仅限 "institutional and professional clients" |

**这是本次调研里最需要正视的信息。**

Ostium 做的**就是你们要做的事**——RWA 永续、股票标的、保证金模式——而且已经跑了 $53B 成交，背后是 Jump 和 Coinbase Ventures。

**但差异仍然存在，且是你们的机会：**
- Ostium 是 **API-first、面向机构**，不做消费者界面
- Ostium **没有公布它部署在哪条链**（官网全篇没提区块链），大概率不是 Monad
- Ostium 的叙事是"基础设施"，你们的叙事可以是"**Monad 上第一个 RWA 永续 + 可交互演示**"

**路演时的风险**：如果评委知道 Ostium，会问"你和 Ostium 什么关系"。**必须准备答案**——建议方向：Ostium 是机构 API 层，Koliance 是 Monad 原生的可组合合约层（任何 Monad 上的应用都能直接组合你们的仓位），是**不同的抽象层级**，不是竞品。

### 3.4 Lighter

- 以太坊 zk rollup 上的永续 DEX
- 正在用 Pyth Index 从加密扩展到 RWA
- **不是 Monad 上的**，但是同一个叙事方向。说明"RWA 永续"是当前行业共识方向，不是你们瞎想。

### 3.5 竞品格局小结

| 项目 | 链 | 机制 | 标的 | 阶段 |
| --- | --- | --- | --- | --- |
| **Perpl** | Monad | 链上 CLOB | 加密(BTC) | $1B+ 成交 |
| **Kuru** | Monad | CLOB+AMM 现货 | 加密 | Paradigm 领投 |
| **Ostium** | 未披露 | 池子/API | **RWA 全品类** | $53B+ 成交 |
| **Lighter** | ETH zkRollup | — | RWA 扩展中 | 已上线 |
| **Koliance** | **Monad** | **GMX v1 式金库对手盘** | **RWA 美股** | **待建** |

**空位是真实存在的**：Monad 上没有"金库模式的 RWA 永续"。Perpl 占了链上 CLOB + 加密，Ostium 占了 RWA 但不在 Monad 且是机构 API。

## 第五部分：对你们方案的三条实质影响

### 5.1 时间线是硬约束，不是"黑客松冲刺"的修辞

`项目目标.md` 说"以黑客松冲刺为基准"，但没写具体日期。**真实截止日是 10 月 13 日，距今 8 天。**

`执行方案-后端与合约.md` 排的是 5 天（Day 0.5 + 3 + 2 + 1.5），**已无缓冲**。而且规则要求代码必须是六周内新写的——你们不能靠已有仓库"省时间"。

**建议**：立刻确认是否真的投 Metropolis。如果要投，`推进方案.md` 里"砍 TradingView K 线"这类优化**不用讨论了，直接砍**。

### 5.2 定位要往"Monad 原生"上靠，不要做成通用 GMX fork

证据链：
- Track 1 官方样例："**perpetuals whose funding refreshes each block**"
- Monad 共识路线图：Cadence 目标 100ms 出块
- Perpl 已经用 "fully onchain CLOB" 占住了"链上订单簿"叙事
- Ostium 已经用 $53B 成交占住了"RWA 永续 API"

**剩下的空位**：把**逐块资金费率**做成真实可演示的东西。别的链做不了这个（资金费率通常 1h/8h 更新一次），这正好是 Monad 性能的用武之地，也正好是官方给出的话题。

> 这比你 `推进方案.md` 里现在的写法更进一步——原文只做到"批量清算"，那是性能展示；"逐块资金费率"是**机制创新**，评委更买账。

**(1) "你们的结算价从哪来？"**
