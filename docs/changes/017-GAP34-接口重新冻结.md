## 缺口

`推进方案.md:34-37` 在阶段 0 冻结了 `IPositionManager`，目的是让前端与 Go Bot **并行开工**。
GAP-07 给 `closePosition` 补了 `minOutUsd` / `deadline`，**冻结被破坏**。
接口里的注释写着「**预期它还会变**」——此后一直处于「**已破冻结、未重新冻结**」的状态。

代价不只是文档不同步：**任何想并行开发的消费方都无法确信接口是稳的**。

---

## 做了什么

### 1. 设计文档对齐到实际签名

`推进方案.md` 的冻结段原写于**前瞻口径**（`IVault` 只列 3 个函数、`IPositionManager` 只写
「开仓/平仓/liquidate」）。现更新为**实际签名**，并注明与初稿的两处差异：

| 差异 | 原因 |
| --- | --- |
| `closePosition` 多了 `minOutUsd` / `deadline` | GAP-07 |
| 新增 `openPositionFor` | `ADR-004` 的 Agent 委托路径 |

实测确认其余两条属实：`IVault` 的 `addLiquidity` / `removeLiquidity` / `totalAssets` 与
`IPriceOracle` 的 `getPrice` 签名**与文档一致**（未改动）。

### 2. 接口里的权威冻结清单

`IPositionManager.sol` 文件头新增 **FROZEN SURFACE** 清单，写明：

> **这份清单是权威，不是任何规划文档。**规划文档描述的是写作当时的意图；
> 当它与本清单冲突时，**以本清单为准**——那是代码实际做的事。

清单含 **20 个函数签名 + 5 个事件**。事件一并冻结的理由与函数相同：
**链下索引器从事件回填**，改签名与改函数一样破坏兼容。

并把原来的「预期还会变」改为：
> **已重新冻结。**（this signature changed once, and the change is now closed）

同时诚实标注：模块**仍未部署**，所以这是对**接口形状**的承诺，**不是**"地址已存在"的宣称。

### 3. 把冻结变成机械约束，而不是注释

**注释拦不住任何人。** 新增 `contracts/test/perp/FrozenSurface.ts`：
读编译后的 ABI，逐条断言冻结集完好。动一个签名就得**刻意改这里**——
这正是"冻结"该有的摩擦。

**刻意不覆盖**清单之外的函数：**新增是扩展，不是破坏**，守卫不该阻碍它。
故第三条用例是一道**守卫的守卫**——断言冻结集是 ABI 的**真子集**；
若有人从 ABI 整体重新生成这份清单，冻结就退化为"ABI 恰好是什么"，不再拦得住任何东西。

## 负向证伪：守卫有牙齿

注入两处变异（改函数签名的期望、改事件签名的期望）：

```
closePosition(uint256,uint256,bytes[]) -> now closePosition(uint256,uint256,uint256,bytes[])
PositionLiquidated: inputs uint256,address,address,uint256,uint256 (frozen: uint256,address,uint256,uint256)
```

**两条守卫都报错，且给出精确可操作的差异**——不是"某个断言失败"，而是
"你期望的签名 vs 实际存在的签名"。工作区已还原。
