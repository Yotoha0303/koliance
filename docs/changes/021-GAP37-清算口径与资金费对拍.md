## 问题

`PositionPanel` 同屏给出两个数，口径不同却都不标：

| 元素 | 口径 | 来源 |
| --- | --- | --- |
| 「可清算」徽章 | 链上判定，**含**资金费 | `PositionManager.isLiquidatable` |
| 「预估强平价」 | 纯价格公式，**不含**资金费 | `src/lib/perp.ts` 的 `liquidationPrice` |

资金费非零时二者会互相矛盾（`015` 已实测：前端对拍重生成可洗白前端，**链上对拍仍抓住**）。

## 根因：资金费项**从未有过跨边界对拍**

`docs/changes/015` 建立了黄金向量对拍把 `liquidationPrice` 钉在链上，但 **`LiquidationParity.ts:81` 刻意把资金费率设为 0**：

```ts
// See the header note: the price formula is what is under test here.
await pm.write.setFundingRatePerBlockWad([0n]);
```

`015` 同时记下 `tests/perp.test.ts` 的往返断言是**资金费盲且自洽**的。于是**资金费项既无链上对拍、又只有自洽测试**——这正是 GAP-37 能藏身的地方。

**所以只加公式不加对拍，等于上一个没有验证的财务公式**（D3）。

## 做法

### 1. `src/lib/perp.ts`：新增 `liquidationPriceWithFunding`

解 `collateral + pnl - funding == mm`：

```
long :  P = entry * (mm - collateral + funding + size) / size
short:  P = entry * (collateral + size - mm - funding) / size
```

关键约束：`liquidationPriceWithFunding(p, 0n)` **必须与 `liquidationPrice(p)` 逐位相同**。
故把后者改成**前者的资金费为零的特例**（共享同一实现），二者**在结构上无法漂移**——
GAP-06 的 60 条向量就此**顺带**保护了这条不变量。

### 2. 资金费感知的对拍（前后端各一半）

| 半边 | 文件 |
| --- | --- |
| 前端 | `tests/liquidation-funding-parity.test.ts` + `tests/liquidation-funding-vectors.ts` |
| 合约 | `contracts/test/perp/FundingLiquidationParity.ts` |
| 向量 | `contracts/test/perp/fixtures/liquidation-funding-vectors.json`（48 条） |

**资金费额不交给合约当参数**，而是由 `elapsedBlocks` + `fundingRateWad` 推出，合约侧靠**真的累积资金费**复现。
于是合约必须同时同意**欠费额**与**它隐含的边界**——资金费公式或价格公式任一侧漂移都会红。

**三处刻意的设计**（都踩过坑）：

1. **费率在开局前设好**——仓位在开仓时记录资金费指数，事后设费率会让它被收取未持仓区间的费用。
2. **用反复调用 `accrueFunding` 而不是挖块**——`_projectedFundingIndex` 在「上次累积就在本区块」时返回存量，
   故挖块会让 `elapsed` **差一**。一次调用一个区块，`elapsed` 才恰等于向量的 `elapsedBlocks`。
3. **每条向量只开一个仓位**——单边簿 skew 恰为 ±WAD，每块增量坍缩为 `elapsed * rate`，与簿子规模无关。
   代价：每条向量的仓位都**在拥挤侧、因此付费**；收费侧由 `tests/perp.test.ts` 以数值形式覆盖。

费率取 `MAX_FUNDING_RATE_PER_BLOCK_WAD`（1e13）**上限**：资金费项要足够大，否则「漏算资金费」的公式会**落在边界同一侧**，
对拍就会为它本该抓的 bug 而通过。

### 3. `PositionPanel`：两个口径都留、各自标清

- 「预估强平价」→ **「强平价（纯价格）」**
- 新增 **「强平价（含资金费）」**（网格 4 列 → 5 列）
- 原「GAP-37 残留」注释改写为「两个数回答不同问题，故意并列」

**负向证伪（已实跑，非声称）**：

| 注入 | 预期 | 实测 |
| --- | --- | --- |
| 丢弃资金费项后跑**前端**对拍 | 红 | ✅ `funding vector #1 drifted` |
| 丢弃资金费项 + **重新生成向量**再跑**合约**对拍 | 红 | ✅ `one wei the safe side` 用例失败：`liq=2000000000000000000` 恰等于入场价，链上在 safer 一侧就清算 |

> **第二条第一次没红，值得记下**：只变异 `perp.ts` 不重新生成向量，**合约侧仍然绿**——
> 因为合约侧的输入是**向量文件**，不是 `perp.ts`。要证伪它，必须**连同向量一起重生成**。
> 这说明「前端对拍 + 合约对拍」是**两道独立的门**，也说明**只跑其中一道会漏**。
