## 关键发现：Hardhat 3 没有阈值配置，且 lcov 不含分支数据

### （1）配置只有 `skipFiles`

读了 `node_modules/hardhat/dist/src/internal/builtin-plugins/coverage/config.js`：

```js
const userConfigType = z.object({
    coverage: z.object({
        skipFiles: z.array(z.string()).optional(),
    }).optional(),
});
```

**没有 threshold 字段。** 所以 `hardhat test --coverage` 的报告纯粹是信息性的——
覆盖率下降时 CI 依然全绿。这正是 `提示词.md` 纪律 §3 要杜绝的"虚假全绿"。

### （2）报告不含分支数据

实测 `coverage/lcov.info` 的记录类型统计：

```
BRF: -> 0 条
BRH: -> 0 条
BRDA: -> 0 条
LF:  -> 13 条
LH:  -> 13 条
```

**Hardhat 3 的 lcov 只写行覆盖，不写分支覆盖。**

### （3）由此产生的虚假全绿（**本次实现中真实犯过**）

第一版 `check-coverage.ts` 用 `found === 0 ? 100 : ...` 处理空分母，
于是报告上每个文件都是 **`branches 100.00%`**——在一个**根本不含分支数据**的报告上。

这是比没有门禁更糟的情况：它会一直绿着，而分支覆盖可以烂掉。
发现方式是**自己怀疑了那个 100% 并去 grep 原始文件**。

**已修**：`pct()` 空分母返回 `null`，显示为 `n/a`，且**明确打印"分支覆盖不受门禁约束"**。
若将来 Hardhat 开始输出 `BRDA`，`MIN_BRANCH_PCT` 会自动生效。

## 新增：`contracts/scripts/check-coverage.ts`

读 `coverage/lcov.info`（`hardhat test --coverage` 已经产出），
对 perp 模块算总行覆盖率，低于阈值则 **exit 1**。

### 统计范围（只算生产合约）

```
contracts/perp/PositionManager.sol
contracts/perp/Vault.sol
contracts/perp/PythOracleAdapter.sol
contracts/perp/DemoOracle.sol
contracts/perp/MockUSDC.sol
contracts/perp/utils/Ownable.sol
contracts/perp/utils/SafeCast.sol
```

**为什么排除 mocks**：`MockERC20` / `MockPyth` / `MockPositionManager` 是测试替身，
它们"未覆盖的分支"就是"测试不需要走的分支"，计入只会拉低数字而不说明生产代码质量。
**`MockUSDC` 不排除**——演示里它就是真实抵押品，与替身不同。

**为什么排除 `Koliance.sol` / `KolToken.sol`**：属于身份模块，不在 perp 工作流内，各有其既有覆盖率。

### 阈值

| 指标 | 实测 | 阈值 |
| --- | --- | --- |
| 行覆盖 | **93.98%** | **93%** |
| 分支覆盖 | 无数据 | n/a（不约束） |

阈值**刻意设在实测值下方一点**：设在当前值会在下一次无关重构时失败，
然后被赶时间的人删掉；低一点仍能拦住真实回归，且不会变成噪音。数字涨上去后再抬。

### 当前分文件数据

```
DemoOracle.sol          lines  94.29%
MockUSDC.sol            lines 100.00%
utils/Ownable.sol       lines 100.00%
utils/SafeCast.sol      lines  50.00%   ← 最低
PythOracleAdapter.sol   lines  89.41%
PositionManager.sol     lines  96.15%
Vault.sol               lines  88.04%
TOTAL                   lines  93.98%
```

`SafeCast.sol` 50% 是合理的：它的两个 `toInt256` / `toUint256` 溢出分支需要构造
超 `type(int256).max` 的数值，而现有测试没有走到——**它是一个真实的覆盖缺口，不是错误**。
未列入本次修复范围（见台账）。

## 负向证伪检验（纪律 §3）

**一个从不失败的门禁等于没有门禁**，所以必须验证它会红：

```powershell
# 把阈值改到高于实测值，必须 exit 1
const MIN_LINE_PCT = 99;   # 临时改
npx tsx scripts/check-coverage.ts
```

**实测输出**：
```
  TOTAL                        lines  93.98%   branches    n/a
  floor                        lines  99.00% (99%)   branches    n/a (not gated)
✗ Coverage below floor: lines 93.98% < 99%
  exit=1
```

**恢复后**：
```
✓ Coverage above floor
  exit=0
```

另一条负向路径：报告文件缺失时打印如何生成，并 `exit 1`（不是静默通过）。
