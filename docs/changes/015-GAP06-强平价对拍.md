## 缺口是什么

`推进方案.md` 的风险表把这条列为**"演示当场对不上，可信度崩"**：

> 前端强平价 ≠ 链上清算价 —— `src/lib/perp.ts` 与合约共用常量

而 `src/lib/perp.ts:300` 的注释声称与合约**逐位一致**（"bit-for-bit"）。**从来没有任何东西验证过这个声明。**

GAP-06 原本被标注为「需要链上部署 / 依赖 GAP-16」——**这个判断是错的**：
一致性在**进程内 hardhat 链**上就能验证，不需要部署到任何网络。

---

## 为什么不直接 import（试过，不通）

最直接的做法是让合约测试 import 前端的 `liquidationPrice`。**实测失败**：

```
error TS6059: File '.../src/lib/perp.ts' is not under 'rootDir' '.../contracts'
  File is CommonJS module because '.../package.json' does not have field "type"
```

抬 `rootDir` 能让 `tsc` 通过，但**运行时仍然炸**：

```
Error: Cannot find module './perpConfig'
  Require stack: - .../src/lib/perp.ts
```

根因是 `contracts/` 是 `type: module`（ESM）而根不是（CJS），`perp.ts` 内部那行
`from "./perpConfig"`（无扩展名）在 tsx 的 CJS 加载器下解析不了。
**这正是 `执行记录-Phase0.md:218` 记过的"问题 2"**——跨目录导入触发 ESM/CJS 冲突，
当时的结论是"共享文件的位置由最少权限的那一方决定"。本次不推翻它。

## 采用的做法：黄金向量

```
src/lib/perp.ts ──(tests/liquidation-vectors.ts 同一份网格)──┐
                                                              ├─→ fixtures/liquidation-vectors.json
tests/liquidation-parity.test.ts  ── 对比实时输出 ────────────┘
contracts/test/perp/LiquidationParity.ts ── 读同一份文件，在链上重放
```

**两个文件、一份向量**，比对三件事：

| 比较 | 失败发生在 |
| --- | --- |
| 前端(实时) == 向量 | 前端套件 |
| 合约(链上) == 向量 | 合约套件 |
| **前端 == 合约** | 由上面两条蕴含——**这才是要证的** |

**向量网格刻意挑难看的角落**：杠杆 1x / 2x / 10x / 25x / 50x 全覆盖；
抵押 100 与 1000 USDC；入场价含 **33,333**（公式有两次整数除法，除不尽的值最容易分道扬镳）；
多空两个分支各走一遍。共 **60 条**。

> ⚠️ **一个必须对齐的口径**：链上存的 `collateralUsd` 是**扣完开仓手续费**的净额。
> 向量用 `netCollateralUsd()` 取净值——用毛额就是拿两个不同的量在比，
> **错的是向量不是代码**。

## 合约侧测的是"边界"，不是"某个 wei"

两条断言，**缺一不可**：

1. **在广告的强平价上，链上必须判定可清算**（60 条全过）。
   失败时打印实际权益，让报告说的是"差多远"而不是"不一样"。
2. **再往安全侧偏一个 wei，必须仍然活着**。
   只有第 1 条会放过"清算得过早"的公式——那在台上读起来就是
   **"链上在我看到的数字之前就吃掉了我的仓位"**。

> 只断言**边界**、不断言**精确到 wei**，是因为合约用 `<=` 且整数除法截断。
> 诚实的说法是"这就是边界"，不是"就是这个 wei"。

**资金费率置零**：前端的 `liquidationPrice` 只建模价格公式；资金费是另一项，
有自己的前端对应物（`isLiquidatableWithFunding`，在 `tests/perp.test.ts` 里覆盖）。
开着资金费就是把**无资金费的数**与**含资金费的判定**相比，会因为跟公式无关的原因失败。

## 变异测试：证明这份判据有牙齿

**通过的测试如果不会失败，就毫无价值。** 故对判据本身注入了故障：

| 步骤 | 结果 |
| --- | --- |
| 给多头分支注入 `+ entryPrice/100`（1% 偏差） | — |
| ① 前端对拍（不重新生成向量） | **变红**：`vector #0 drifted` ✅ |
| ② 用 `UPDATE_VECTORS=1` 重新生成向量（模拟"把漂移洗白"） | 向量被改写成变异值（liq 2 → 3.6） |
| ③ 前端对拍 | 此时**通过**——说明它单独不够 |
| ④ **合约对拍** | **仍然抓住**：`chain says NOT liquidatable (equity 1.998e18)` ✅ |

**第 ④ 步是这份设计的价值所在**：即使有人用"重新生成向量"来消掉前端测试的红，
**链上那一侧依然会失败**。两侧检查各司其职，一条都不能少。

现场已完整还原（残留变异标记 0）。
