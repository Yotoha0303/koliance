## 新增：`contracts/contracts/perp/SessionKeyRegistry.sol`

414 行。链上锚定用户的委托：主钱包签一次 EIP-712 结构化授权，任何人可验证。

**结构**（对齐 `agentcard` 与 `SessionKey` 实体已用的字段名，避免第四套模型）：

```solidity
struct Delegation {
    address user;  address agent;  address sessionKey;
    uint256 maxSpendPerTx;  uint256 dailySpendLimit;  uint256 validUntil;
    uint256 nonce;  uint256 spentInWindow;  uint256 windowStart;
    bool exists;  bool revoked;  bool frozen;
}
```

**三处刻意的设计决定**：

1. **`registerDelegation` 收 `user` 参数，不用 `msg.sender`**。
   自治叙事的要点是**Agent 提交授权并付 gas、用户签一次就走**。签名即授权，
   中继者改不了任何一个字段——改了摘要就变，`ecrecover` 就失败（有测试）。
2. **拒绝可延展签名（high-s）**。否则 `(r, s, v)` 与 `(r, n−s, v^1)` 还原出同一地址，
   同一份授权有两个编码。
3. **日窗口会滚动**。RFC 的 Redis 版没有——`daily_spent` 永不归零，
   用户触顶一次即永久受限。那是 **GAP-21**，本合约用显式的 `windowStart` 规避，
   并有专门的回归用例。

**刻意不含**：不动任何代币（授权与托管分离，session key 被盗也动不了金库）、
不用 Redis、**没有"无限额"逃生门**（没有额度约束的委托不叫委托）。

## 新增：测试 19 例——正向 7 + **证伪 12**

证伪用例是这份文件的价值所在。每一例都是委托系统常见的一种错法，且**必须响亮地失败**：

| 证伪用例 | 攻击面 |
| --- | --- |
| 签名后被改字段（中继者把小额度改大） | 签名必须无法还原 |
| 用别人的私钥签 | 必须拒绝 |
| **可延展签名**（s → n−s, v → v^1） | 同一授权不得有两个编码 |
| 单笔超额 / 单笔合规但破日限 | 双额度都要咬住，且**被拒的那笔不得消耗额度** |
| 注册时已过期 / 花费时已过期 | 时效 |
| 路人燃烧他人日窗口 | `NotAuthorizedCaller` |
| 委托给自己 | `SelfDelegation` |
| **把已占用的 session key 改绑给他人** | `SessionKeyAlreadyBound` |
| 零额花费（用 no-op 滚动窗口） | `ZeroAmount` |
| 对未注册的 key 操作 | `NoSuchDelegation` |
| 撤销后重放原签名 | **`NonceAlreadyUsed`——撤销必须不可逆** |

**互操作用例（GAP-24 的正面回应）**：`viem` 链下签的摘要与合约 `delegationDigest`
**逐字节比对**。GAP-24 记录了三套互不兼容的 Session Key 模型且**无代码验证任何两者一致**——
这一例就是那个缺失的验证。它把不一致暴露为**摘要比对失败**，而不是一笔莫名其妙的 revert。
