## 新增：`backend/internal/perp/position`

头寸数学的 Go 镜像 + 并发安全头寸表 + 批量扫描。

**为什么需要镜像而不是每笔都问链**：Bot 每个价格 tick 要扫全部头寸。
逐个 `isLiquidatable(id)` 是 N 次 RPC 往返，延迟直接摧毁"1 秒内清算数十笔"的目标。
镜像在本地算，只对**判定为可清算**的才发交易。

**镜像的一致性风险与对策**（这是本包的核心）：

| 风险 | 对策 |
| --- | --- |
| 整数除法顺序不一致 → 阈值差 1 wei | 与 Solidity **完全相同的运算顺序**，并用 ±1 wei 边界测试钉死 |
| Go 的有符号除法有两种舍入 | 只用 `big.Int.Quo`（向零截断，同 Solidity），**绝不用 `Div`**（向负无穷取整）。有专门测试 |
| 权益下限截断不一致 | `Equity()` 显式 floor 到 0，同 `_equityAfter` |
| 判定用 `<` 而非 `<=` | 用 `<=`，同 `_isLiquidatable`。有"恰好等于阈值必须可清算"的测试 |

测试用的数字**与 Solidity 测试套件相同**（999 抵押 / 10x / 入场 180），
所以"Go 通过"意味着"与合约一致"，而不是"与另一份猜测一致"。

### 关键测试

| 测试 | 断言 |
| --- | --- |
| `TestNotLiquidatableOneWeiAboveTheThreshold` | 强平价 +1 wei **不可**清算 |
| `TestLiquidatableOneWeiBelowTheThreshold` | 强平价 −1 wei **可**清算 |
| `TestLiquidatableAtExactlyTheThreshold` | 恰好等于强平价**可**清算（`<=` 语义） |
| `TestPnLTruncatesTowardZero` | `(-2)/3` 必须为 `0`；用 `Div` 会得 `-1` |
| `TestLiquidationPriceForTenXLongMatchesTheContract` | 严格落在 (163, 164) USD，同 Solidity 的手算值 |
| `TestScanResolvesEachFeedOnce` | 10 笔同 feed 只调 1 次价格查询，不是 10 次 |
| `TestScanReportsPositionsWithNoPrice` | 无价格的头寸**进 skipped 列表**，不被当作"健康"静默跳过 |
| `TestTableIsConcurrencySafe` | 在 `-race` 下读写混合无告警 |

**`Scan` 按 feed 分桶的理由**：`liquidate(ids, updates)` 在**一次调用内所有头寸共用同一个价格快照**。
所以同一次调用里的头寸必须同 feed、同价格。混 feed 需要合约持有多个快照，而它不做这件事。

## 新增：`backend/internal/perp/nonce`

本地 nonce 分配器。这是 `执行方案-后端与合约.md:311-321` 标记的**死保项**。

**为什么不能用 `PendingNonceAt` 逐笔取**（注释里写了完整时序）：

```
t1: PendingNonceAt -> 7
t2: PendingNonceAt -> 7      ← t1 还没广播，节点仍报告 7
t1: 用 nonce 7 发送
t2: 用 nonce 7 发送          ← 其中一笔被丢弃
```

**两笔清算只落地一笔，而批量调用"看起来"成功了**，头寸静默保持未清算。
这正是演示会死的地方。

**三条设计约束**：

1. **在广播前才分配**，不在构造批次时分配 —— 构造后被放弃的批次不该烧掉一个 nonce。
2. **允许空洞，绝不复用** —— 广播失败会留下空洞。Ethereum 接受跳过 nonce 8 直接打包 9。
   而复用有风险：被丢弃的交易可能还在某个 peer 的 mempool 里。
3. **`Resync` 只前进，不后退** —— 节点报出比我们已发放的更小的 nonce 时，
   它要么滞后、要么 mempool 视图不同；照做会**重新发放一个在途的 nonce**，
   正是本类型要防的碰撞。"nonce too low" 报错时才需要向前追平。

### 关键测试

| 测试 | 断言 |
| --- | --- |
| `TestConcurrentAllocateNeverDuplicates` | 32 goroutine × 250 次 = 8000 个 nonce **两两不同且连续无空洞** |
| `TestResyncRefusesToMoveBackward` | `Resync(3)` 后 `Peek()` 仍是 100 |
| `TestResyncMovesForward` | 追平后从新值继续 |
| `TestPeekDoesNotConsume` | 连续两次 `Peek` 返回同值 |
| `TestAllocateReportsExhaustion` | 到 uint64 上限返回 `ErrExhausted` |
