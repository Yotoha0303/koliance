## 背景

---

## 关键发现：70.35% 是个假象

装上 provider 后第一件事是**先量再说**，得到的全树读数是 **70.35% lines**。但这个数字是假的：

```
# 不加 include 时，v8 只统计"被测试 import 过"的文件
$ npx vitest run --coverage
Statements : 66.66% ( 164/246 )
Lines      : 70.35% ( 159/226 )      # 只有 226 行参与统计

$ npx vitest run --coverage --coverage.include='src/**'
Lines      : 7.89% ( 159/2015 )      # 2015 行
```

**两者的区别不是口径偏好，而是门禁有没有用**：不加 `include` 时，
**新增一个谁都没 import 的组件，覆盖率数字一点都不会降**——恰恰是门禁最该抓的情况它抓不到。
它会长期全绿，同时生产代码在无人测量地增长。

这与 `003` 记录的那次"空分母当 100%"是同一类错误：**数字是真的，结论是假的**。

---

## 决策：门禁范围 = perp 逻辑核心

两个候选都不理想，实测后取了折中：

| 范围 | Lines | Branches | 问题 |
| --- | --- | --- | --- |
| 全树 `src/**` | 7.89% | 4.6% | 数字被无测试的 UI 主导，只能说明"demo 外壳没有测试"，**已知且不是门禁的职责** |
| **`src/lib/perp.ts` + `perpConfig.ts`** | **76.74%** | **60%** | 范围窄，但窄得**故意** |
| 逻辑核心 + UI（`PositionPanel.tsx`、`/perp` 路由） | 25.78% | 16.75% | 会把整条 perp 工作流压到 25%，阈值只能定得极低 |

采用第二行。**理由对齐合约侧**：`contracts/scripts/check-coverage.ts` 也是用
`INCLUDED_PREFIXES` 只门禁 perp 模块，而不是 `contracts/` 全树——同样的思路，同样的范围口径。

门禁盯的是**demo 真正依赖的数学**（强平价、保证金率、清算赏金、杠杆校验），
那里静默回归就是台上的事故。

### 阈值：实测值下方数点

| 指标 | 实测 | 阈值 |
| --- | --- | --- |
| Lines | 76.74% | **72** |
| Branches | 60% | **55** |

**刻意低于实测**，理由写在 `check-coverage.ts` 的注释里、由它自己的首次 CI 失败换来：
**贴着实测值定的地板，会在下一次无关重构时变红，然后被赶时间的人删掉**。
低几点仍能抓住真实下滑。

> ⚠️ 与合约侧的差异：Hardhat 只输出 line 记录（无 `BRDA`），所以那边只门禁 lines；
> v8**有** branch 数据，故这边两个都门禁。

## 改动

| 文件 | 改动 |
| --- | --- |
| `package.json` | `@vitest/coverage-v8@^4.1.11`（**必须与 `vitest` 4.1.11 同版**；先装的 5.0.3 报 `unmet peer`）+ `test:coverage` 脚本 |
| `vitest.config.mts` | `coverage: { provider: v8, include: [perp.ts, perpConfig.ts], thresholds: { lines: 72, branches: 55 } }` |
| `.github/workflows/ci.yml` | frontend job 的 `npx vitest run` → `npx vitest run --coverage` |
| `.gitignore` | 加 `coverage/`（同区 `artifacts/` 的写法，**无内部斜杠故任意层级匹配**——GAP-36 的反面示范） |

**CI 那一步为什么必须改**：`coverage.thresholds` **只在采集覆盖率时生效**。
CI 若仍跑裸的 `vitest run`，配置里的地板在 CI 上**根本不会被应用**——
本地绿、CI 也绿，而门禁从未生效。步骤名已改为 `Unit tests with coverage` 以免误读。

**证明它抓的是"真实覆盖率下降"，而非只是数字装饰**：往 `src/lib/perp.ts` 追加
约 20 行无任何测试覆盖的代码（含分支的循环与三元链），再跑：

```
 All files      |   62.83 |    50.76 |    72 |   68.04 |

```

Lines 76.74% → **68.04%**，Branches 60% → **50.76%**，**两条阈值同时报错**。
工作区已用备份完整还原（`git diff --stat` 为空）。
