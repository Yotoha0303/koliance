## 背景

`提示词.md` 十环 03 环准出要求：

> 所有新建测试用例 **100% 纳入 CI 自动执行矩阵（拒绝门外用例）** + 覆盖率采集配置阈值

实测 `Test-Path .github` → `False`。即：134 个用例（hardhat 120 + vitest 14）**只在开发者本机跑过**，
没有任何机制能在 PR 上拦住一个让测试变红的改动。这也正是 GAP-01~05 能长期存在的原因之一——
它们对应的用例此前根本不存在，而即便存在也不会被强制运行。

## 新增：`.github/workflows/ci.yml`

**三个独立 job**，而不是一个。理由：三条工具链的安装方式完全不同，
且前端安装失败不应掩盖合约编译失败。

| job | 工具链 | 安装方式 |
| --- | --- | --- |
| `contracts` | Hardhat 3 + solc 0.8.31 + viem | `npm ci`（`contracts/` 是独立 npm 工程，有自己的 `package-lock.json`） |
| `frontend` | Next.js 15 + vitest | **`pnpm install --frozen-lockfile`** |
| `backend` | Go 1.25 | go modules |

**为什么根目录必须用 pnpm 而不是 npm**（GAP-28）：
根 `package-lock.json` 已陈旧（不含 `@supabase/supabase-js`），`npm ci` 会装出一棵
`tsc` 跑不过的依赖树。`pnpm-lock.yaml`（`lockfileVersion: '9.0'`）才是权威。
实测：在未 `pnpm install` 时 `npx tsc --noEmit` 报 **23 个错误**。

**为什么 `contracts` 单独跑 `tsc`**：`npx hardhat compile` 只编译 `.sol`，
测试文件与 ignition 模块里的跨模块类型错误**永远不会被它发现**。
这条在本次立即生效——见下节。

**为什么前端跑 `next build`**：`tsc` 通过但渲染失败的情况是存在的
（例如 client component 访问浏览器全局），只有构建能拦。

其他：`concurrency` 取消同 ref 的过期运行；`pull_request` 无 branches 过滤，
这样针对任意 base 的 PR 都会被检查。

## 附带修复：3 个既有类型错误

CI 一加上就红了，这**正是它的价值**。三个错误中**两个不是本分支引入的**：

| 文件 | 错误 | 来源 | 修复 |
| --- | --- | --- | --- |
| `contracts/scripts/deploy-kol.ts:7` | `TS2339: Property 'name' does not exist on type 'NetworkManager'` | **上游 `79e7073`** | `network.name` → 解构 `networkName` |
| `contracts/scripts/transfer-test.ts:18` | 同上 | **上游 `79e7073`** | 同上 |
| `contracts/test/perp/SolvencyGuards.ts:170` | `TS2345: Argument of type 'undefined' is not assignable to 'AssertPredicate'` | **本分支 `0193e3a`** | 去掉多余的 `undefined` 占位参数 |

**关于前两个（他人代码）**：Hardhat 3 已把 `network.name` 改为 `networkName`，
但 `contracts/tsconfig.json` 的 `strict: true` + `@types/node` 解析使这个属性访问在类型层失败。
这两个脚本**从未被 `hardhat compile` 检查过**（compile 只碰 `.sol`），所以一直没暴露。
修复方式与我在 `scripts/demo-seed.ts` 中已验证的写法一致（该脚本 `tsc` 通过）。

> 如果上游对这两个文件有别的意图，可以只取 CI 文件、把这两处回退——
> 但那样 CI 会红，所以建议一并接受。**这是协同改动，已在提交信息中标注。**

（尤其 `forge-std` 从 GitHub 拉取的 `github:foundry-rs/forge-std#v1.16.2`）需首次运行时确认。
